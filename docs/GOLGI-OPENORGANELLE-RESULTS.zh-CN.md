# 引入 OpenOrganelle 数据对高尔基体分割的影响：四组实验

[English](GOLGI-OPENORGANELLE-RESULTS.md) ｜ **中文**

> 结论：**没有改善。** 联合训练的 last5 为 0.3188，仅自有数据为 0.3245，
> 差 −0.0057，落在 3 种子的波动范围（±0.016）内——既不能说改善，也不能说变差。
>
> 但过程中有两个必须记录的发现：不做对比度归一化时，混合训练会把模型**彻底毁掉**
> （last5 0.0009）；而 OpenOrganelle 内部跨细胞类型也几乎不泛化（0.0072）。

---

## 1. 实验设计

前提：自有高尔基体标注是**部分标注**，48 张图里 17 张覆盖率低于 3%，
分层证据显示覆盖率 <3% 时 Dice 仅 0.0900、预测面积是真值的 10.8 倍。
若能把公开数据里**完整标注**的高尔基体引入，理论上可补上这个缺口。

数据来自 OpenOrganelle 的 `groundtruth` crop，四个经核实有高尔基体标注的 crop 中
真正可用的三个（crop48 的 golgi 仅 0.05%，实质为空）：

| crop | 形状 (z,y,x) | golgi 前景 | 细胞 |
|---|---|---|---|
| `jrc_hela-2` / `crop4` | 476×600×600 | 6.12% | HeLa |
| `jrc_jurkat-1` / `crop37` | 400×400×400 | 29.17% | Jurkat |
| `jrc_macrophage-2` / `crop39` | 400×400×400 | 25.63% | 巨噬细胞 |

切成 256×256 瓦片后得 **6648 个**（5071 正 + 1577 负）。
注意 crop37 与 crop39 的每一块都含前景（占比 25–29%），
**负样本全部来自 crop4**——这会让背景校准依赖单一来源。

四组实验：

| 编号 | 训练 | 验证 | 目的 |
|---|---|---|---|
| B | OO + 自有（归一化） | 自有留出 281 | 能否提高我们自己的分数 |
| B' | OO + 自有（原始灰度） | 自有留出 281 | 同上，但不做归一化 |
| C | OO 的 crop4+crop37 | OO 的 crop39 | OO 内部能否泛化 |
| A | 仅 OO（归一化） | 自有留出 281 | 纯跨域迁移的天花板 |
| 对照 | 仅自有 | 自有留出 281 | 基线 |

B' 因明显失败提前停止（13/60 轮）；A 只跑 15 轮（同为失败，跑满没有信息增益）；
B、C 与对照跑满。

超参与既有基线一致：U-Net base 32、256 输入、batch 16、Adam 3×10⁻⁴、种子 0。

## 2. 结果

| 实验 | 轮数 | best | last5 | final | 非零轮 |
|---|---|---|---|---|---|
| **B** OO+自有（归一化） | 60 | 0.3402 | **0.3188** | 0.3215 | 58 |
| **B'** OO+自有（未归一化） | 13 | 0.0619 | **0.0009** | 0.0000 | 3 |
| **C** OO 跨细胞类型 | 40 | 0.0540 | **0.0072** | 0.0076 | 39 |
| **A** 仅 OO（归一化） | 15 | 0.0481 | **0.0242** | 0.0255 | 15 |
| **对照** 仅自有 | 60 | 0.3605 | **0.3245** | 0.3445 | 60 |

既有 3 种子结果（同口径）：best 0.4242 ± 0.0506，last5 0.3180 ± 0.0080。

**B 与对照的差为 −0.0057，两倍种子标准差为 0.0160。**
因此不能声称这批公开数据带来了改善；单种子也不足以声称它有害。

**A 与对照的差为 −0.30**（0.0242 对 0.3245）——这两个数字的差距不需要统计检验，
是三十倍的量级差。即：单纯用公开数据训练，在我们的图像上几乎不可用。

---

## 3. 三个必须记录的发现

### 3.1 不做归一化会彻底毁掉模型

第一版直接把 OO 的原始灰度与自有数据混在一起训练，结果：

```
epoch 1/60  loss 0.6492  val dice=0.000
epoch 5/60  loss 0.6234  val dice=0.000
epoch 10/60 loss 0.6166  val dice=0.000
epoch 13/60 loss 0.6123  val dice=0.000
```

连续 10 轮验证 Dice 精确为 0.000，而仅自有的基线在第 12 轮已到 0.2592。
这不是起步慢，是被拖坏了。

原因在强度分布上：

| | 均值 | 标准差 | <64 像素 | >192 像素 |
|---|---|---|---|---|
| OpenOrganelle | 172.7 | **12.3** | 0.0% | 2.3% |
| 自有 TEM 插图 | 140.8 | **56.9** | 10.8% | 19.1% |

OO 的对比度只有自有的**四分之一**，且没有一个像素低于 64。
在共享的 0–255 输入尺度上，它看起来是一片平灰，编码器无从学习膜结构。
当 81% 的训练样本都是这种近乎无纹理的图时，模型学会的就是"什么都不预测"。

逐块做 1%–99% 百分位拉伸后，两者可比：

| | 均值 | 标准差 | <64 像素 |
|---|---|---|---|
| OO（拉伸后） | 149.4 | **66.0** | 12.4% |
| 自有 | 140.8 | **56.9** | 10.8% |

模型随即恢复正常学习（第 4 轮 0.067、第 5 轮 0.135）。

**这一步只对 OO 做**：若连自有数据一起归一化，基线也要重训，
与既有的 0.3180 就不再可比。

### 3.2 拉伸会同时放大噪声

对比图显示，拉伸后的 OO 切片有了纹理，但主要是**高频噪声**而非膜结构。
结构确实存在——对齐验证时在 crop4 的 z=3905 处能清楚看到平行的池层带——
但它不是均匀分布的，有些区域除了标注之外几乎无内容。

所以**有效可用数据量低于瓦片数**。这一点无法从"6648 个瓦片"这个数字看出来。

### 3.3 OO 内部跨细胞类型也几乎不泛化

实验 C 用 HeLa 与 Jurkat 训练、巨噬细胞验证，40 轮后 last5 仅 **0.0072**。

这比"用 OO 训练去预测我们的插图"（0.000）好不了多少。
说明 OpenOrganelle 内部不同细胞类型之间的差异，已经和我们与它之间的差异相当。

含义是：**这批数据的价值不在"拿来就能用"，而在"体数据 + 完整标注"这个组合本身**
——若要做迁移，需要针对目标域做适配（例如少样本微调），而不是直接混合训练。

## 4. 结论与建议

**结论一**：把 OpenOrganelle 的高尔基体数据与自有数据联合训练，未能提高自有留出集上的
Dice（0.3188 对 0.3245，差 −0.0057，在种子波动内）。

**结论二**：只用公开数据训练，在我们图像上的 Dice 为 0.0242，而仅用自有数据为 0.3245
——**三十倍的差距**。公开数据不能替代自有标注，哪怕它有完整标注。

**结论三**：直接混合而不处理强度差异，会造成灾难性失败（0.0009）。
这是本项目里"数据处理比模型更重要"最直接的一个例子。

**结论四**：OpenOrganelle 内部跨细胞类型的泛化也很差（0.0072）。
所以问题不只是"我们与它之间"的域差异，而是这类数据本身的异质性就很高。

综合起来：**对结项而言，补齐那 17 张低覆盖率图像仍然是唯一有证据支持的提升手段**；
分层数字表明把覆盖率补到 8% 可使均值超过 0.5。公开数据提供的是方法与参照，
不是标注的替代品。

### 若继续，值得做的下一步

1. **少样本微调**：以 OO 预训练的权重为起点，只用少量自有数据微调，
   而不是把两者混在一个训练集里。这利用了 OO 的形态知识而避免其外观主导。
2. **按细胞类型分层验证**：确认 C 的低分有多少来自巨噬细胞与 HeLa 的形态差异。
3. **按有效纹理筛样本**：用局部方差筛掉近乎无内容的瓦片，
   再看可用瓦片数与结果的关系。

以上均未执行，不应被当作已有结论。

## 5. 复现

```bash
# 取数（四个 crop，约 1.7 GB）
python tools/oo_locate.py
python tools/oo_fetch_crops.py --out data/oo --workers 24

# 建切片（逐块百分位拉伸）
python tools/oo_to_tiles.py --src data/oo --out data/oo_tiles --classes golgi

# 三组实验
bash tools/server/scripts/train_golgi_oo.sh

# 汇总
python tools/golgi_oo_summary.py
```

产物位置：`data/oo/`（原始体）、`data/oo_tiles/`（瓦片）、
`runs/oo_plus_ours/`、`runs/oo_golgi_indomain/`、`runs/seg_golgi_own/`（训练记录）、
`logs/golgi_oo.log`（完整日志）。
